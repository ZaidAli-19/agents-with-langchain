# Story 1.1 — Architecture and Project Seed

## Purpose

Agree on the architecture, then seed a small Python project that lets Open WebUI talk to Gemini through LangChain. This is the first story of the beginner LangChain and LangGraph course. The capstone is a **Learning Companion Chatbot**.

Project path: the repository root (no `docs/config.yaml` configures another path).

## What this story implements in plain English

After this story, a participant can:

- Start a small local application with one command.
- Open the chat window they already use (Open WebUI) and pick the model the instructor named.
- Type a message and see a reply from Gemini in that window.
- See the reply appear word by word, or all at once, depending on how the chat window asks for it.
- Start the application with no secret key set, and get a clear message about the missing key only when they try to chat.

## Prerequisites

- Python 3.12 and [UV](https://docs.astral.sh/uv/) are installed.
- Open WebUI is already installed and working. It is the supplied chat client only. Do **not** reinstall, reconfigure, modify, or build it.
- The instructor has supplied the Gemini model name and each participant has their own Gemini API key.
- Existing files in the repository (`README.md`, `docs/prompts/`) are preserved. The seed's `README.md` replaces or extends the current one only by merging, never by deleting the handout content without keeping it elsewhere.

`.env.example` must contain exactly these setting names:

```
APP_ENV=development
GEMINI_API_KEY=
GEMINI_MODEL_NAME=
HOST=127.0.0.1
PORT=8000
```

Document in `.env.example` comments and in `README.md`: the instructor supplies the model name; participants put their real key only in their untracked `.env`. Add no Claude, alternate-provider, database, or production configuration.

Application behaviour:

- **Startup:** the app starts with no real API key. Missing key or model name produces an honest configuration error (a clear OpenAI-style error JSON with a non-2xx status) only when a model call is attempted, never at startup.
- **`GET /health`:** returns a simple OK response.
- **`GET /v1/models`:** returns an OpenAI-compatible model list exposing the configured `GEMINI_MODEL_NAME` as the selectable model. If it is blank, return an empty list.
- **`POST /v1/chat/completions`:** accepts the normal OpenAI-compatible request shape needed by Open WebUI: `model`, a list of text `messages` with roles `system`, `user`, or `assistant`, and `stream`.
  - `stream: false` → normal OpenAI-compatible JSON chat completion.
  - `stream: true` → text-only OpenAI-compatible SSE chunks, then a stop chunk, then `data: [DONE]`.
  - No custom Open WebUI events, no second chat route, no custom browser UI.
- **LangChain flow (seed only):** one prompt → Gemini chat model → text output. The prompt has a fixed Learning Companion instruction (kept separate from user text) plus the latest user message. The same flow serves both normal and streaming requests. Keep it deliberately small. Full prompt construction and conversation history are Story 2.1.

Do not add a broad test suite, tool calls, LangGraph, agents, MCP, or advanced streaming features.

**Expected classroom result:** one Gemini reply visible in Open WebUI, selected from the model listed by `GET /v1/models`.
